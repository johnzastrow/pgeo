# Rebuilding Everything

This is the authoritative runbook for rebuilding the final iteration of both platforms from an
empty checkout: the shared data, **Pelias**, **pgeo** (PostgreSQL/PostGIS), the demo page, the
verification suites, the deployment to the query host and the study report. Every step is a script
in this repository; this document explains what each one does, how long it takes and how to check it.

Detailed background for the data steps (sources, pinned versions, checks, licences) is in
[DATA_PIPELINE.md](DATA_PIPELINE.md); pgeo deployment details in [DEPLOY_PGEO.md](DEPLOY_PGEO.md);
tuning in [TUNING_REPORT.md](TUNING_REPORT.md).

## 1. Requirements

| Item | Needed for | Notes |
|------|-----------|-------|
| Linux workstation, 6+ cores, 24+ GB RAM, ~40 GB free disk | all builds and tests | builds were measured on a Ryzen 5 3600 / 31 GB (report, Section 3.5) |
| Docker Engine with Compose v2 | everything | images are pinned by tag or digest in the compose files |
| `uv` | Python tools (`prep/`, `pgeo/`, `report/`) | each is its own project with a lock file |
| `git`, `curl`, `python3` | scripts | |
| Ansible (core 2.16+) with `ansible.posix` | deployment | `infra/ansible/` |
| `pandoc` and `xelatex`, fonts Noto Sans and DejaVu Sans Mono | the PDF report | without them the report builds as Markdown only |
| Playwright with Chromium (`pip install playwright && playwright install chromium`) | browser smoke test | |
| SSH access to the Proxmox host and the query VM | deployment, VM tests | key in the SSH agent |
| Optional: OpenAddresses token in `projects/pelias_maine/secrets.env` | none today | the statewide Maine file is used without a token |

Secrets never enter git: `projects/pelias_maine/secrets.env` (Pelias) and `pgeo/pgeo.secrets`
(generated by `scripts/pgeo_setup.sh`) are gitignored and mode 600; the query host generates its
own pgeo secrets.

## 2. One command

```bash
scripts/rebuild_all.sh              # check, data, pelias, pgeo, verify, report  (about 1.5-2 hours)
scripts/rebuild_all.sh pgeo verify  # any stages, in the order given
scripts/rebuild_all.sh deploy       # ship to the query host (explicit only)
```

| Stage | What runs | Time | Result |
|-------|-----------|------|--------|
| `check` | tool check | seconds | "tools ok" |
| `data` | `scripts/bootstrap.sh`, `scripts/fetch_data.sh all`, `pelias-prep all` | 10-20 min (downloads) | `data/raw/*`, `data/processed/csv/{gnis,zcta,overture}.csv` |
| `pelias` | `scripts/build_local.sh setup download prepare import up test`, `scripts/snapshot_local.sh` | ~30 min | Elasticsearch index `pelias` (1,649,644 documents), snapshot `pelias-<date>` |
| `pgeo` | `scripts/pgeo_setup.sh`, `scripts/pgeo_rebuild.sh` | ~20 min (first image build adds ~10 min) | database `pgeo` (906,101 features), profile applied, accuracy gate passed |
| `verify` | compatibility contract, pgeo unit tests, browser smoke test | ~3 min | "compat: passed", "OK" |
| `report` | `scripts/build_report.sh --refresh` | ~1 min | `docs/REPORT.md`, `docs/REPORT.pdf`, `docs/REPORT.docx` |
| `deploy` | `scripts/pgeo_dump.sh`, Ansible `site.yml` | ~15 min | both engines live on the query host |

## 3. Stage by stage

### 3.1 Data (shared by both engines)

```bash
scripts/bootstrap.sh                 # pelias/docker CLI at a pinned commit -> vendor/pelias-docker
scripts/fetch_data.sh all            # OSM extract, GNIS, ZCTA, state boundary, Overture places, basemap
(cd prep && uv run pytest -q && uv run pelias-prep all)   # GNIS, ZCTA, Overture -> Pelias CSV
```

Checks and expected counts: DATA_PIPELINE.md sections 3-4. The Pelias download step in 3.2 also
fetches Who's On First, OpenAddresses and TIGER and converts OpenAddresses to the CSV form that
both the Pelias interpolation builder and pgeo read (`pelias-prep oa-interp`).

### 3.2 Pelias

```bash
scripts/build_local.sh setup download prepare import up test
scripts/snapshot_local.sh            # prints the snapshot name for deployment
```

`setup` refuses to run if an index exists; to rebuild, drop it first:
`(cd projects/pelias_maine && ../../vendor/pelias-docker/pelias elastic drop)`. Configuration:
`projects/pelias_maine/` (compose file with pinned images, `pelias.template.json`, synonyms).
Checks: DATA_PIPELINE.md sections 6-8 (document counts per source, test suite 19 pass / 13
expected failures).

### 3.3 pgeo

```bash
scripts/pgeo_setup.sh --profile workstation                     # once: secrets, images, containers, edge
scripts/pgeo_rebuild.sh --profile workstation -f pgeo/compose.pinned.yml
```

`pgeo_rebuild.sh` runs, and stops at the first failure:

1. `pgeo-load build`: loads WOF, OpenAddresses, OSM, GNIS, ZCTA and Overture, assigns the admin
   hierarchy by point-in-polygon, deduplicates, indexes, applies every SQL function
   (`pgeo/sql/0*.sql`, which carry all ranking tuning), swaps the new schema in atomically and runs
   `VACUUM (ANALYZE)`;
2. `pgeo-tune apply <profile>`: PostgreSQL and front-end settings from `pgeo/tuning/profiles/`,
   verified against the running server;
3. `pgeo-tune verify`: eight known-answer queries through FastAPI and the pure-SQL API;
4. the accuracy and fuzz sets against the pure-SQL API and the gate
   (`tests/accuracy/gate.py`, baseline `tests/accuracy/baseline.json`).

Endpoints afterwards (all on 127.0.0.1): database 5433, FastAPI 4500, PostgREST 4600, pure-SQL edge
with Pelias paths 4700. Profiles for other machine sizes: `uv run --project pgeo pgeo-tune list`;
for sizes in between, `pgeo-tune auto --cpus N --mem-gb M --write`.

### 3.4 Demo page (local)

```bash
scripts/dev_web.sh                   # http://127.0.0.1:8088 with production headers and CSP
```

Locally the page offers three engines (Pelias, pgeo pure SQL, pgeo FastAPI), the Address tab
(USPS addresses from pgeo) and the Compare tab. Vendored libraries: `scripts/vendor_web.sh`.

### 3.5 Verification

```bash
uv run --project pgeo python tests/compat/compat_test.py     # Pelias API contract, 28 cases
(cd pgeo && uv run pytest -q)                               # parser, tuning tools, SQL address functions
python3 tests/web/smoke_demo.py                              # browser test, every tab and engine
uv run --project report --with pytest pytest report/tests -q # the report renderer (37)
uv run --project pgeo pytest tests/security -q               # deployment posture (30 deployed)
uv run --project pgeo --with jinja2 pytest tests/web/test_engine_modes.py -q  # one engine or two
uv run --project pgeo python tests/accuracy/run_accuracy.py --engine pgeo --base http://127.0.0.1:4700 --label check
uv run --project pgeo python tests/accuracy/gate.py data/accuracy/pgeo-check.json
```

### 3.6 Deployment to the query host (VM 120)

```bash
ssh root@192.0.2.10 'qm set 120 --memory 14336 && qm reboot 120'    # once: both engines need 14 GB
scripts/rebuild_all.sh deploy
```

The `deploy` stage dumps pgeo (`scripts/pgeo_dump.sh`), finds the newest Elasticsearch snapshot and
runs `infra/ansible/site.yml` with both names and forced restores. Roles: `base` (hardening),
`docker`, `pelias_runtime`, `pgeo_runtime` (official PostGIS and PostgREST images; secrets generated
on the VM), `edge` (nginx: demo page, `/v1/*` to Pelias, `/pgeo/v1/*` to pgeo, engine switch).
TLS terminates on the wharf Caddy (`infra/wharf/pelias.caddy`). Rollback of pgeo:
`ansible-playbook site.yml -e pgeo_enabled=false`. Details: DEPLOY_PGEO.md.

### 3.7 Report

```bash
scripts/build_report.sh              # from saved results (seconds)
scripts/build_report.sh --refresh    # refresh live facts and the compatibility contract first
scripts/build_report.sh --refresh-accuracy   # also re-run the accuracy and fuzz sets (~15 min)
```

Inputs are listed in `report/inputs.toml`; point it at new load-test run ids after re-running them.

## 4. Load tests and experiments (hours; run on purpose, not by rebuild_all.sh)

| Script | What | Time | Output |
|--------|------|------|--------|
| `python3 tests/load/run_matrix.py [--configs C1,..] [--datasets D1,..]` | Pelias capacity matrix; data-volume subsets | 2-4 h | `data/loadtest/<run>/` |
| `python3 tests/load/run_matrix_pgeo.py --engines rest,api --configs Pmin,P1,P2,P4,PM` | pgeo capacity matrix | 5-7 h | `data/loadtest/<run>-pgeo/` |
| `python3 tests/load/run_matrix_pgeo.py --engines rest --configs E1,E2,E4` | pgeo at Pelias's memory budget, for the equal-resources comparison | 3-4 h | `data/loadtest/<run>-pgeo/` |
| `python3 tests/load/run_datavol_pgeo.py --configs P2` | pgeo capacity against data volume: rebuilds from each D1-D5 subset and ramps | 4-6 h | `data/loadtest/<run>-pgeo-datavol/` |
| `python3 tests/load/find_floor.py --engines pgeo,pelias` | smallest configuration that serves 3 users | 1-2 h | `data/loadtest/<run>-floor/` |
| `python3 tests/load/find_floor.py --resume data/loadtest/<run>-floor --only cpus` | continue an earlier floor search after adding smaller steps | 30-60 min | `data/loadtest/<run>-floor/` |
| `tests/load/floor_vm.sh <engine> <vmid 190-199> <cores> <cpulimit> <mb> ...` | the found minimum on a temporary Proxmox VM (created, tested, destroyed) | 30-60 min | `data/loadtest/<run>-vm/` |
| `python3 tests/load/run_vm.py` | both engines on VM 120 through HTTPS (raise the edge rate limits for the window) | 1-2 h | `data/loadtest/<run>-vm/` |
| `python3 tests/build/measure_build.py --engine <e> -- <build command>` | build time, CPU, memory, disk | 15-30 min | `data/buildstats/` |
| `uv run --project pgeo python tests/accuracy/run_accuracy.py ...` | accuracy (1,560 cases) or fuzz (1,800 cases) | 3-5 min | `data/accuracy/` |

**After any load-test run, restart the engines it stopped.** `run_matrix_pgeo.py` and
`run_datavol_pgeo.py` bring up only the front end under test, so the other one is left down and
the compatibility contract will report every case against it as a failure:

```bash
docker compose --env-file pgeo/pgeo.secrets --env-file pgeo/tuning/active.vars \
  -f pgeo/compose.yml up -d db api rest
```

Method, targets and caching: [LOAD_TEST_PLAN.md](LOAD_TEST_PLAN.md) and
[TESTING_GUIDE.md](TESTING_GUIDE.md). Load tests pin the engine and the load generator to separate
physical cores; do not run other heavy work on the same machine meanwhile.

## 6. Troubleshooting (lessons from this project)

- **Edited config not picked up by a container**: files bind-mounted one at a time keep pointing at
  the old inode if an editor replaces the file. Recreate the container (or edit in place).
- **A generated file disappeared after `git pull --rebase`**: replaying a commit that stopped
  tracking a file deletes the working copy. Re-generate it (`pgeo-tune apply <profile>` for
  `active.conf`).
- **Pelias subset or restore fails right after a restart**: Elasticsearch needs time to become
  ready; the load runner waits for cluster health, scripts that call it directly should too.
- **Load-test runs cut short without an error**: check `journalctl -u docker`; a stopped Docker
  daemon ends every container at once.
- **pgeo reverse geocoding slow**: `feature_admin_idx` must exist (the build creates it); without
  it every reverse request scans all features.
